# 构建计划

> 每个阶段是有边界的交付物，不做阶段外功能。

## 阶段总览

| 阶段 | 交付物 | 状态 |
|---|---|---|
| 0 基础骨架 | Vite + React 静态站跑通 | 已完成 |
| 1 数据层 | 家常菜库 + 食材营养数据（手工子集） | 已完成 |
| 2 个人资料 | 表单 + localStorage 保存 | 已完成 |
| 3 规则引擎 | 三高判定规则 + 默认阈值 | 已完成 |
| 4 推荐 UI | 单餐推荐 + 原因解释 | 未开始 |
| 5 收尾 | lint/build/测试 + 文档校正 + 部署 | 未开始 |

## 各阶段明细

### 阶段 0：基础骨架
- 包含：Vite + React 脚手架、静态站能 `npm run build`、空壳首页
- 排除：数据、表单、规则、推荐
- 验收：`npm run dev` 打开页面；`npm run build` 成功

### 阶段 1：数据层
- 包含：`Dish` 类型、家常菜库 JSON（30–50 道）、食材营养 JSON 导入与字段裁剪
- 排除：UI、规则
- 验收：数据可被脚本校验（字段齐全、无缺失关键营养值）

### 阶段 2：个人资料
- 包含：表单 UI、`UserProfile` 校验、localStorage 保存与读取
- 排除：推荐逻辑
- 验收：填资料→刷新→资料仍在

### 阶段 3：规则引擎
- 包含：`Meal` 类型、默认指南阈值常量、硬过滤（忌口）、一餐组装（按自选菜数）、硬指标整餐判定 + 其他逐菜判定、单元测试
- 排除：推荐 UI
- 验收：单元测试覆盖边界（忌口排除、硬指标整餐超限排除、其他指标逐菜排除、默认阈值兜底、自选菜数组合）

### 阶段 4：推荐 UI
- 包含：自选菜数控件、一餐组合推荐展示、逐菜营养 + 整餐硬指标合计、推荐原因（为何符合/为何排除）
- 排除：多人、摄入记录
- 验收：填入资料 + 自选菜数后，能得到符合限制的一餐组合推荐

### 阶段 5：收尾
- 包含：`lint` / `build` / 测试、文档校正、部署说明、提交推送
- 排除：新功能
- 验收：`git diff --check` 干净；测试全绿；文档与代码一致

## Git 与回滚

- 开发分支：`feat/food-planner`
- 每个阶段开始前：在 `main` 上建立远程备份分支（如 `backup/food-planner-<phase>-<date>`）
- 禁止：`git reset --hard` / `git clean -fd` / `git push --force` / `git checkout -- <file>`
- 回滚优先：`git revert <bad-commit>`
